# UPME 本番DB 利用状況分析

集計日時：2026年11月9日 14:51 JST

## 分析対象と確認方法

- ローカルの接続設定を使い、Supabase の `public.users` を読み取り専用で取得した。
- 接続先：`woxotmmgvabizjgizwow.supabase.co`
- 最新の登録ID 3件について、Releaseビルドの接続先 `https://aisns-1.onrender.com/api/users/{user_id}` と照合。投稿数・フォロワー数・オンボーディング完了状態が3件とも一致した。
- 登録日時で範囲を固定してページ分割し、対象1,103件を取得。取得件数とDBの対象件数が一致し、IDの重複はなかった。
- 読み取った項目：照合・重複確認用ID、`created_at`、`total_posts`、`total_followers`、`has_completed_onboarding`。
- このレポートにはユーザーID、名前、アバター、認証キー、個別のユーザーレコードを含めていない。DBへの更新・削除・DDL実行はしていない。

## 最初に押さえる結論

1. 全体の56.4%（622/1,103件）が累計3投稿以下。登録から30日以上経ったIDでも54.5%（474/869件）が3投稿以下だった。直近の新規登録だけでは、この偏りを説明できない。
2. オンボーディング完了は86.2%（951/1,103件）。そのうち212件、22.3%は累計投稿数が1だった。現行アプリはオンボーディング完了時に投稿数を1に設定するため、これらは通常投稿がまだ記録されていない状態と解釈できる。ただし過去バージョンの挙動・同期不整合は別途考慮が必要。
3. 10投稿以上のIDも24.6%（271件）、51投稿以上は33件ある。少数の高投稿数に平均が引き上げられるため、平均9.53投稿より中央値3投稿を重視する。
4. このDBスナップショットでは、翌日・7日後の継続率、DAU、最終利用日、離脱原因は算出できない。低投稿数をそのまま離脱認定しない。

## データ品質と計測上の限界

- オンボーディング未完了だが投稿数が1以上：4件。
- オンボーディング完了だが投稿数が0：2件。
- 投稿数のNULL・負数、フォロワー数の負数、登録日時のパース不能、取得ID重複：いずれも0件。
- これらの不整合6件について、同期・旧バージョン・テストなどの原因は未特定。
- `total_posts` と `total_followers` はクライアントから上書き同期するカウンターであり、監査可能なイベント履歴ではない。
- ページ分割による読み取りはDBトランザクションのスナップショットではないため、読み取り中に更新されたカウンターが混在する可能性はある。
- 計測対象の `users` に最終利用日時・投稿日時の履歴・アプリバージョン・常連AI設定履歴がなく、継続率・機能効果・バージョン別比較を計算できない。
- 現行実装では投稿本文・AI返信は端末保存が中心であり、今回のデータから投稿内容のポジティブ／ネガティブ分類や返信品質を分析したわけではない。

## 改善の優先順位（データを踏まえた仮説）

### 1. オンボーディング後の最初の通常投稿

完了IDの22.3%が累計1投稿であることから、通常投稿への導線、何を書くかの提案、通信エラーや返信待ちの体験を優先して確認する。DBだけではどれが原因かは分からない。

### 2. 数投稿以内に分かる変化

全体の半数超が3投稿以下であるため、育成・進化・演出解放などを導入するなら、最初の通常投稿で小さな変化が見え、数投稿以内に節目を体験できる設計を検証する価値がある。解放条件を長期利用の先に置くと、現時点で低投稿数の層は体験できない。

### 3. 常連AIなど、既存の継続要素を早く体験できるか

常連枠上限の緩和や初期の常連紹介を検討できる。ただし常連利用と再訪の関係を測ってから判断する。今回のDBには常連設定履歴がないため、効果は未検証。

### 4. PostHogで再訪とエラーを確認

以下はアプリに計測イベントが実装されているが、今回はPostHogの実データを取得していない。

- 初期導線：`onboarding_started` → `onboarding_post_submitted` → `onboarding_completed` → `post_created`。
- 再訪：`daily_active`、`session_start`。初回通常投稿を起点にした翌日・7日後の再訪も見る。
- 返信体験：`ai_replies_request_started`、`ai_replies_received`、`ai_replies_displayed`、`ai_replies_failed`。別イベント間の厳密な待ち時間分析には投稿・リクエスト単位の識別子なども確認する。
- 関係性：`regular_follower_added` と再訪・投稿の関係。ただし機能を使う人は元々高頻度かもしれず、単純比較を因果効果としない。
- 集計前に本番・開発イベントの混在、イベント欠損、タイムゾーン、旧バージョンと同意状態による計測対象の違いを確認する。

このレポートを根拠に行う優先判断は「まず初期の数投稿の体験を調べる」。キャラクター育成が継続率を上げると証明されたわけではなく、導入する場合も再訪と通常投稿数への効果を検証する。
