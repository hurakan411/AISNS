# 30種類のキャラクター：ローカル実生成テスト

## 結論・手動確認の所見

- 2026-11-18実施。30人×3投稿の90返信を含め、24回のAPI呼び出し・120返信を保存。全呼び出しで正常解析、5人分の順番・キャラID・常連IDを確認した。
- 穏やかな丁寧語、気さくな短文、軽いユーモアなどの違いは出る一方、「おつかれ」「いいね」などに収束する組み合わせも多い。30種類が明瞭に区別できることを証明したものではない。
- 既存の短文・中文・長文の割当が強く、先頭のキャラが長く丁寧になりがち。定義で軽快なタイプでも返信位置に引っ張られた例がある。今回、各5人グループの並び順は3投稿で固定したため、キャラ効果と返信位置の効果を切り分けられない。
- 落ち込みへの明確な罵倒・嘲笑・否定は今回のサンプルでは見当たらない。ただし「脳内で延長戦」「今日は閉店」など、つらい場面では軽く受け取られ得る比喩や、複数人による休息の勧めが残った。本番導入前の調整点。
- 常連3人は2投稿で固定キャラIDを維持。これは実験用JSONの往復保存・生成結果の照合であり、iOSの常連登録からの永続化まで確認したものではない。
- 5返信の現行方式と比較した18ケースでは、入力tokensの差は-25〜+4、平均-12.5。既存のリアクション分担指示を置き換えたので、単純にキャラ設定分が上乗せされなかった。
- 入力を30分キャッシュ書込単価、出力を通常単価、1ドル160円で換算した差は平均+0.00328円／5返信の投稿。キャラIDを返す出力項目を含め、出力は平均44.1tokens増えた。ただし各条件1回であり、出力の差をキャラ導入の確定的な因果効果とはみなせない。
- 全24呼び出しのusageからの推計費用は約1.803円。請求実額ではない。30人の定義を毎回送らず、各呼び出しで選択した5人分だけを送った。
- この段階では本番APIの生成経路は変更していない。導入を進める場合は、口調を潰さない長さ指定、つらい投稿での比喩・助言抑制、常連設定のiOS保存、返信スレッド連携、旧アプリ互換性を別途実装・検証する。

合成投稿のみ。Luna / reasoning_effort=none / アンチOFF / 5返信を1回で生成。アプリ・DB・Renderへの組み込みは未実施。
通常投稿の現行プロンプトを取得し、リアクション分担部分だけキャラクター指示へ置換。実験用character_idを出力に追加。
